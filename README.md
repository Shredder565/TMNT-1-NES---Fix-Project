# Teenage Mutant Ninja Turtles (NES, USA) — Source Recovery & Fix Project

**NES only.** This is an experimental reverse-engineering and modding workspace, **not a complete original-source reconstruction**. Most of the game remains preserved as raw data / inferred assembly. Runtime gameplay compatibility has not been verified.

## Current changes

| Feature | Source | Verification |
| --- | --- | --- |
| Leonardo weapon damage matches Donatello (15 / 16) | `mods/leonardo_equal_donatello/source/bank06.asm` | Source rebuild / synthetic unit tests only. **This does not change hitbox size or reach.** |
| Lag experiment (3 CPU cycles saved per tile in one render routine) | `mods/lag_reduction_v1/source/` | Rebuild / static tests. **60 Hz under load is NOT demonstrated.** |
| Keep strong nonboss enemies defeated after revisiting (32+ HP threshold) | `mods/leonardo_strong_enemy_respawn_PROTOTYPE/source/` | **UNTESTED in an emulator.** Do not treat as a completed bug fix. |

See `docs/LEONARDO_DAMAGE_SOURCE.md`, `docs/60FPS_LAG_REDUCTION.md`, and `docs/STRONG_ENEMY_RESPAWN_RESEARCH.md` for the exact work performed and remaining risks. The complete workspace history is in `docs/RECOVERY_PROJECT_README.md`.


## Checkpoint 2 — easier source editing and stronger verification

- **Editable weapon damage values:** modify `config/weapon_damage.json` and run `python tools/edit_weapon_damage.py --variant base` (or `--variant lag`). This generates buildable, labeled 6502 assembly and an IPS patch, changing only authorized damage bytes.
- **Executable combat unit coverage:** `tests/test_combat_cpu_execution.py` now steps through the real 6502 damage selection/subtraction instructions rather than checking the table alone. This is **not** a full NES emulator or in-game validation.
- **No-respawn experiment:** a third direct spawn allocator at bank 6 `$82C9` is now intercepted, with synthetic tests. The persistent-kill prototype is **still NOT gameplay-verified**, and may have New Game/PRG-RAM/actor-slot issues.
- **No-slowdown verification gate:** `tools/check_crowded_lag.py` accepts complete original/modified emulator NMI trace CSVs and applies a crowded-scene zero-skipped-frame gate. **No real traces have yet been captured**, so neither the slowdown nor the overall 60 FPS objective can be declared fixed.
- **One-command validation:** on Windows run `validate_update.bat`, or use `python tools/validate_checkpoint.py`; results are written to `build/CHECKPOINT_VALIDATION.json`.

See `docs/NEXT_VALIDATION_AND_SPRITES.md`. Enemy sprite replacement is intentionally deferred until slowdown and respawn behavior are confirmed in emulator gameplay.

## Build and test

Requires **Python 3**. From this directory:

```bash
python tools/build.py --expect-vanilla
python tools/build.py --source-dir mods/leonardo_equal_donatello/source --output build/TMNT_Leonardo_Equals_Donatello.nes
python tools/build.py --source-dir mods/leonardo_plus_lag_experiment/source --output build/TMNT_Leonardo_And_LagReduction_EXPERIMENTAL.nes
python tools/build.py --source-dir mods/leonardo_strong_enemy_respawn_PROTOTYPE/source --output build/TMNT_Leo_Lag_NoRespawn_UNTESTED_PROTOTYPE.nes
python -m unittest discover -s tests -v
```

Windows users can run `build_character_and_enemy_experiments.bat`. Source banks, rebuild utilities, experimental branches, IPS patch files and sprite editing scripts are included.

**No original or precompiled `.nes` ROMs are included in this GitHub-ready distribution.** The current source and extracted asset banks are sufficient to reproduce the validated baseline. ROM files generated by build scripts are git-ignored. If you add game assets or full ROMs to any public repository, ensure you have the necessary rights and permissions. This project is not affiliated with the game's copyright holders.

## Publish to GitHub

Repository target: `https://github.com/Shredder565/TMNT-1-NES---Fix-Project`

With **Git for Windows** installed and your GitHub credentials configured, open PowerShell in this folder and run:

```powershell
powershell -ExecutionPolicy Bypass -File .\push_to_github.ps1
```

The script clones the target, copies these files and pushes a commit to the `main` branch. It will not delete existing remote files. You may also upload source files through the GitHub web interface manually.
